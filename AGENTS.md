# Working on ubumint

## Scope

- This is the owner's private ubu mint project, separate from uburoom. Read README.md before planning or changing it. The instance run on Cloudflare is saved to `ubumint-cloudflare`.
- The owner updated the DNA schema and uburithm weighting on 2026-10-25 and authorized local .ubu signing, batch storage, the Cloudflare application implementation and a configurable per-account lifetime mint limit. Read docs/dna.md, docs/uburithm.md, docs/ubu-file.md and docs/worker.md before relevant work. Deployment, production keys, creating/configuring external accounts, trading, encryption and uburoom integration remain separate work requiring authorization.
- Keep owner requirements distinct from proposed mechanisms and examples. Do not turn an agent recommendation into an approved protocol decision.
- Keep the repository private. Remote creation, pushes, publication, Cloudflare provisioning and deployment require explicit owner authorization. Never embed mint secrets in uburoom or browser code.

## DNA and ubucodes

- DNA is random input to permanent deterministic generation rules, not merely a serialized list of resulting traits.
- DNA is exactly 512 bits. Assigned field meanings are fixed; future additions use only unassigned bits 374–501. Old 256-bit beta ubus have no compatibility path. Preserve all 64 bytes when reading, storing or exporting. All thirty-two rare material patterns are implemented in the shared renderer with a 5-bit gate (1/32) and 5-bit selector. Preserve their fixed assignments and the default matte treatment for inactive gates.
- Approved layout: 64-bit name seed, five 18-bit attribute slots, 24-bit mouth rolls, 40-bit mouth geometry, 40-bit eye controls, 24-bit lid rolls, 40-bit lid geometry, 20-bit lid flips, 8-bit corner curvature, two six-bit central mouth rolls, 10-bit opening width, 2-bit notch curvature, 128 unassigned bits, final 10-bit Ubuquity. docs/dna.md is authoritative.
- Eyes are solid filled discs with overlaid irises/pupils, not hollow rings. Iris radius equals the prototype opening radius (30.7126), with no seam-concealing oversize. Textures rotate about the ubu outer-circle center.
- The official naming algorithm is the uburithm. Its mechanics and draw order are fixed in docs/uburithm.md. Improve calculation efficiency only while preserving outputs.
- Approved input paths: exact text encoded as UTF-8 then SHA-512 into complete DNA; random DNA generated directly; imported DNA read directly without rehashing. Preserve text case, whitespace and leading zeros. Initialize the name stream directly from the first 64 DNA bits.
- MSB-first bit order, uburithm calculation, slot roles, geometry, curves and finishes are accepted. Default matte and thirty-two material IDs are assigned in docs/dna.md. The working .ubu profile is in docs/ubu-file.md; no encryption is selected.
- Keep DNA interpretation separate from its plain, signed or encrypted transport envelope and host acceptance policy. Never reinterpret failed protected codes as plain codes.
- Two .ubu forms are implemented in ubu-file.js: unsigned/custom DNA and an Ed25519-signed issuance certificate. Both use the 512-bit DNA. Custom ubus never imply official issuance or registered ownership. Signed imports require a caller-trusted mint public key, with no unsigned fallback or file-supplied trust. Hosts may require signed files. The demo has no configured mint trust and imports/exports custom files only; never install test keys as production trust.
- The mint must generate random DNA itself for ordinary minting. Do not authorize caller-selected seeds through the normal mint endpoint.
- Mint-signed certificates include a permanent twelve-digit serial (000000000001–999999999999) covered by the signature. The future registry allocates serials atomically, uniquely per mint, without reuse or wraparound; retries must not mint twice. Custom files have no official serial. This metadata does not alter DNA.
- Approved batch policy: default 1,000, configurable for subsequent batches. Prepare private random DNA/IDs/serials, distribute uniformly without replacement, sign on authorized allocation and start the next batch after exhaustion. Serial order is creation order. mint.js supplies atomic/idempotent allocation; mint-local.js is the Node SQLite adapter. worker.mjs supplies Durable Object storage and alarm scheduling, Discord OAuth and a configurable lifetime allowance (default 0). Enforce allowances in the allocation transaction. Never expose the internal service without authentication; see docs/mint.md and docs/worker.md.
- Ed25519 and exact signing bytes are implemented; production trust distribution, key rotation and mint allowances remain design work. A public verification key must not grant minting authority. Test private keys remain ephemeral and must never be committed or configured as official mint keys.

## Implementation hygiene

- Owner requirement: a lean mint with zero fluff in code, UI, dependencies, tooling and documentation. Every addition must serve a current requirement; do not build speculative functionality or extension infrastructure.
- Use plain JavaScript and platform APIs by default. No framework, generic plugin system, abstraction layer, build pipeline or dependency without a concrete need that the simpler implementation cannot reasonably meet. Development tooling must also justify its cost.
- Keep the mint request path limited to required generation, validation, cryptography and persistence. Rendering and preview work belongs outside that path. Avoid repeated setup, unnecessary allocations, duplicate conversions and unbounded caches; weigh table memory/startup cost against saved work.
- Prefer one implementation of each rule. Keep modules, API surfaces, UI, logs and documentation small and purposeful; do not duplicate protocol specifications across files.
- Optimize against measured bottlenecks and representative workloads. Report CPU/latency, memory, startup and code-size tradeoffs when material. Do not claim absolute optimality or improved performance without evidence; fewer lines alone is not proof of efficiency.
- Efficiency never permits changing approved DNA laws, weakening randomness or cryptography, bypassing authorization or dropping atomic ownership guarantees. Use platform cryptography; do not implement custom cryptographic primitives.
- Keep private keys, tokens, local bindings and state out of Git, logs and examples. Use placeholders in committed configuration.
- Windows production installation: run `install.ps1` from the source checkout to copy current source into sibling `ubumint-cloudflare`, test and deploy; `-DryRun` performs validation without uploading. Owner authorization is required for an actual deployment. Never use Git pull/stash in the deployment copy. Production settings and permanent mint keys live outside Git in `%LOCALAPPDATA%\ubumint\settings.json`; preserve them and never run `-Setup` for an existing mint. `wrangler.jsonc` is the development template; generated `wrangler.deploy.jsonc` is ignored. Keep `keep_vars` enabled and do not replace saved production settings with development defaults. See docs/worker.md.
- Both test scripts default to the dot reporter. Use a detailed reporter only when diagnosing a failure.
- An explicit owner-requested fresh mint reset uses `deploy.ps1 -ResetMint` (or `install.ps1 -ResetMint` to install updates too). It backs up settings and replaces mint identity, signing keys and session secret, retaining deployment/Discord settings and allowance. This selects a fresh registry; it does not physically erase the old Durable Object. Never reset only serial counters under an existing mint identity. Retry a failed reset deployment without `-ResetMint`.
- Run repository commands inside this repository. Do not copy production configuration or data from uburoom.
- Add focused verification for protocol, cryptographic, authorization and accounting boundaries when implemented; setup documentation does not need invented tests.
- Run npm test and npm run test:worker for Worker/auth/mint changes. The latter uses isolated local Cloudflare runtime storage, never a remote deployment. Public assets must use the explicit whitelist in scripts/prepare-assets.cjs; never serve the repository root. ubu-render.js is shared by the designer and site; preserve the owner's finishes and lighting.
